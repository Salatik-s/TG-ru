## Проверка секретов

1. Установите Gitleaks `8.30.1` для своей платформы и проверьте SHA-256 архива по файлу `gitleaks_8.30.1_checksums.txt`. Добавьте исполняемый файл в `PATH`. [Релиз Gitleaks](https://github.com/gitleaks/gitleaks/releases/tag/v8.30.1).
2. Из корня рабочей копии выполните `git config --local core.hooksPath .githooks`. Если в репозитории уже настроены хуки, подключите проверку из `.githooks/pre-commit` к существующему pre-commit.
3. Для полной проверки сначала обновите историю `git fetch --all --tags --prune`, затем запустите `gitleaks git --redact=100 --log-opts=--all .`. В CI этот скан выполняется на каждом PR и при обновлении `main`.

При находке укажите в закрытом отчёте правило, путь, строку, коммит и статус ротации. Значения в отчёт и журнал не копируйте. Исключение допустимо только для проверенного ложного срабатывания с точным отпечатком коммита, файла, правила и строки в `.gitleaksignore`.

Секреты сервисов передаются через окружение или хранилище секретов. Ключи подписи APK и манифеста хранятся вне Git и сервера. Порядок хранения, доступа и ротации должен утвердить владелец до выпуска.
