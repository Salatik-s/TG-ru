# Семейные экраны

Режим поверхности: **Operate**. Основная задача — подключиться и понимать состояние устройства; оформление не конкурирует с перепиской. Это спецификация поведения, без обещания, что возможности реализованы.

## Текущий серверный контракт

В ходе подготовки появился `server/access.mjs`; ниже сопоставление с прочитанной версией, не гарантия будущего API.

| Значение/ошибка | Текст и поведение клиента |
|---|---|
| `new` | «Устройство ещё не подключено»; ввод приглашения |
| `pending` | «Ожидаем одобрения» |
| `approved` | «Устройство одобрено»; можно запросить конфигурацию, но VPN ещё не считается подключённым |
| `blocked` | «Подключение устройства заблокировано»; «Обратитесь к участнику, который управляет доступом»; не предлагать бесконечные повторы |
| `revoked` | «Семейный доступ отозван» |
| `invalid_invite` | «Приглашение недействительно. Проверьте код или получите новое»; причина не конкретизируется как истечение срока, потому что сервер её не разделяет |
| `cooldown`, `rate_limited` | «Слишком много попыток. Повторите позже»; время ожидания только из ответа/заголовка сервера |
| `already_enrolled` | Запросить статус вместо создания новой заявки |
| `expired_or_replayed` | Обновить challenge в протоколе; не показывать пользователю техническое слово challenge |
| `invalid_proof` | «Не удалось подтвердить устройство»; не имитировать одобрение |

`cooldown_until` сопоставлять с `server_time`, не полагаться только на часы телефона. Счётчик не снимает серверную блокировку сам. Название устройства в текущем коде ограничено 80 символами; UI показывает ограничение и сохраняет ввод при ошибке.

Текущий код не содержит отдельного статуса `declined`, отмены заявки клиентом и команды владельца `decline`. Поэтому описанные ниже «Отклонить» и «Отменить заявку» являются целевыми расширениями: **не показывать активные кнопки до появления соответствующих методов**. При текущем контракте владелец может отозвать доступ; такой результат называется отзывом, а не отклонением. Код приглашения пока не содержит адрес сервиса: адрес должен поступать через отдельную конфигурацию/проверенный формат ссылки. Не изобретать поддержку QR или deep link на основании одного поля `code`.

## 1. Навигация

После подключения стартовый экран — обычные чаты Telegram. Поиск, создание сообщения, архив, папки и экран переписки сохраняют структуру выбранной базы. Новая строка «Семейные настройки» добавляется в существующие настройки. Не создавать отдельную нижнюю вкладку ради редкого действия.

«Семейные настройки»:

1. **Подключение** — доступ к семейному сервису и VPN как два отдельных статуса.
2. **Устройства** — текущее устройство; список/заявки доступны только соответствующей роли.
3. **Дополнительные функции** — ghost-настройки и локальная история.
4. **Плагины** — установленные плагины и разрешения.
5. **Безопасность** — блокировка приложения, уведомления, семейный доступ, диагностические данные.

Сводка использует настоящие данные: «Ожидает одобрения», «VPN отключён», «Не удалось проверить». Числа, имена участников, время последнего доступа и версия приложения появляются только из источника данных.

## 2. Первое подключение

### A. Приглашение

Верхний бар «Подключение к семье». Заголовок «Добавьте это устройство». Текст «Откройте приглашение от участника, который управляет семейным доступом». Действия: «Вставить приглашение», вторичное «Сканировать QR-код». Камера запрашивается только после второй кнопки; отказ оставляет вставку.

После разбора приглашения отдельный экран подтверждает **реальный адрес семейного сервиса** и запрашивает имя устройства. Значение по умолчанию берётся из устройства, доступно редактирование. В приглашении может быть секрет: не показывать его целиком, не логировать, не включать в ошибку. Чтение clipboard — только по нажатию; без фонового считывания.

Основная кнопка «Отправить заявку». Под ней: «Заявку должен одобрить участник с правом управления устройствами». Не обещать конкретного времени и не подменять одобрение таймером.

| Состояние | UI и действие |
|---|---|
| Пустой ввод | Поле/вставка доступны; отправка недоступна с понятной причиной |
| Неверный формат | «Не удалось прочитать приглашение. Проверьте, что скопировали его целиком» |
| Истекло, подтверждено сервером | «Срок приглашения истёк» → «Использовать другое» |
| Адрес не доступен | «Семейный сервис не отвечает» → «Повторить» / «Изменить приглашение» |
| Конфликт идентичности сервера | «Не удалось подтвердить адрес сервиса»; не предлагать «Всё равно подключиться» |
| Отправка | Кнопка «Отправляем заявку…»; повторное нажатие не создаёт новую заявку |

### B. Одобрение

Заголовок «Ожидаем одобрения». Ниже — имя этого устройства и адрес сервиса. Текст «Заявка отправлена. После одобрения можно продолжить подключение». Действия «Проверить статус» и «Отменить заявку». Уход назад сохраняет заявку; отмена делает отдельный запрос и подтверждается только ответом сервера.

Нет сети: текущий известный статус остаётся, рядом «Нет связи с семейным сервисом». Отказ: «Заявка отклонена» и «Использовать другое приглашение». Одобрение переводит к настройке подключения только после проверенного ответа. Отзыв уже одобренного устройства — самостоятельное состояние, не общая сетевая ошибка.

Экран управляющего: название устройства, время запроса, серверные сведения, при наличии — реально реализованная сверка отпечатка. Кнопки «Одобрить» и «Отклонить». Не использовать доверенные зелёные badges на основании названия устройства. При ошибке действия заявка остаётся в списке.

### C. Подключение VPN

Заголовок «Подключите семейный VPN». Показать адрес и фактическую область действия: «Только FamilyGram» либо «Весь трафик устройства» — строго из реализации. Далее «Продолжить» вызывает системное разрешение Android, если оно требуется.

Состояния сервиса, VPN-туннеля и Telegram раздельны:

| Слой | Пример текста | Что доказывает |
|---|---|---|
| Семейный доступ | «Устройство одобрено» | Только статус доступа |
| Туннель | «VPN подключён» | Только подтверждённое состояние туннеля |
| Telegram | «Подключение к Telegram…» / статус базы | Только состояние соединения клиента |

Отмена системного диалога: «Разрешение на VPN не выдано» → «Повторить». Обрыв: «VPN отключён». Если трафик действительно блокируется, пояснить «Передача данных приостановлена до восстановления VPN»; иначе не обещать блокировку. Если VPN необязателен по продуктовой модели, «Продолжить без VPN» доступно с честным описанием. Если обязателен, такого действия нет.

Не смешивать VPN с SOCKS/MTProto-прокси. Если реализуется прокси вместо VPN, экран называется «Прокси», системное разрешение VPN не упоминается. Смена адреса показывает последствия и требует явного сохранения; данные текущего соединения не теряются после ошибки ввода.

### D. Вход в Telegram

Стандартный flow базы Telegram: телефон, код, дополнительные шаги при необходимости. Семейный сервис не запрашивает код Telegram в своей форме. Ошибки аутентификации обрабатывает существующий клиент. Семейное одобрение не означает вход в Telegram.

## 3. Дополнительные функции

### Ghost

Заголовок «Дополнительная приватность», подзаголовок «Параметры ghost-режима». Не использовать общий переключатель «Стать невидимым».

Каждая возможность — отдельная строка с точным названием, например «Не отправлять статус набора» **только если эта функция реализована и проверена в клиенте**. Описание сообщает, какие события подавляются и где остаются ограничения. Неактивная/неподдерживаемая возможность объясняет причину и не выглядит включённой.

До технической проверки разрешён экран с текстом «Доступных функций пока нет». Запрещены обещания незаметного чтения, полного скрытия online и обхода серверных ограничений. Выход из экрана не делает неприменённый выбор активным.

### Локальная история

Основная строка «Сохранять удалённые сообщения»; начальное предложение — выключено. Перед включением отдельный лист:

> FamilyGram может сохранять на этом устройстве сообщения, которые успел получить до удаления. Это отдельная локальная копия. Удалённые ранее сообщения восстановить нельзя.

Финальную формулировку сузить до реально сохраняемых типов данных; не обещать медиа, если сохраняется только текст. Действия «Включить» / «Отмена».

Локальная копия визуально отделена от живой переписки меткой «Локальная копия · удалено в Telegram» и датой из реальных данных. Она не подделывает текущее состояние сервера и не меняет индикатор прочтения. Из чата доступно «Открыть локальную историю», но не общая свалка системных событий.

Настройки: поддерживаемый срок хранения, объём только при вычислении, «Удалить локальную историю». Диалог: «Удалить локальные копии?» → «Копии на этом устройстве будут удалены. Переписка в Telegram не изменится». Кнопка «Удалить копии»; завершение только после очистки. Выключение записи не маскирует старые копии: отдельно предложить сохранить или удалить накопленное.

## 4. Плагины

Пустое состояние: «Плагины не установлены» и «Здесь появятся расширения, которые вы добавите». Кнопка добавления существует только при готовом поддерживаемом способе установки.

Строка плагина: реальное имя, версия, источник, состояние. Не рисовать «Проверен» без установленного механизма проверки; валидная подпись сама по себе не означает безопасность плагина.

Перед включением: отдельный экран «Разрешения плагина». Отображать из manifest только те capability, которые реально ограничиваются средой исполнения. У каждой — человеческое объяснение доступа. Примеры категорий для будущего контракта: чтение выбранных сообщений, отправка сообщений по действию пользователя, файлы, сеть. Это примеры, не объявленная поддержка.

Если доступ технически не ограничен, писать это явно; не показывать ложные независимые переключатели. Главная кнопка «Разрешить и включить»; вторичная «Отмена». Новая версия, расширяющая доступ, остаётся выключенной до согласия. Отзыв разрешения должен сразу останавливать соответствующую возможность; если требуется перезапуск, сказать об этом до подтверждения.

Ошибка загрузки: «Плагин не запущен» + причина из безопасного кода ошибки. Кнопки «Повторить» и «Удалить». Никаких stack trace/токенов в обычном экране.

## 5. Безопасность и отзыв

Строки для доступных функций: «Блокировка приложения», «Текст в уведомлениях», «Семейные устройства», «Локальные данные». Описание говорит о конкретном результате; не общий показатель «Уровень защиты 100%».

Детали устройства: источник сведений и статус актуальности. Отзыв: «Отозвать семейный доступ?» → «Устройство потеряет доступ к семейному сервису». Очистку локальной истории, выход из Telegram и удаление VPN-ключей обещать только при наличии и проверке отдельных механизмов. Если эти действия не реализованы, не включать их в текст подтверждения.

После подтверждённого отзыва локальное приложение показывает «Семейный доступ отозван», останавливает зависимые функции согласно контракту и предлагает новое приглашение. Это не подмена статуса Telegram-сессии.

Диагностика открывается по действию пользователя. Состав отчёта виден до экспорта; приглашения, токены, ключи, коды входа и содержимое сообщений исключены. Не отправлять отчёт автоматически.

## 6. Acceptance checklist

- Настоящий телефон или эмулятор: 360×800 dp, 412×915 dp; landscape/split-screen. При поддержке планшета — 800 dp ширина, master/detail.
- Light/dark × font scale 1.0/1.3/2.0: кнопки, ошибки, имена устройств и длинные адреса не обрезаны.
- TalkBack проходит каждый сценарий; переключатель читается один раз, новая ошибка объявляется и остаётся доступной.
- Поворот, background/resume и process recreation не создают повторную заявку; последний известный статус помечается при устаревании.
- Сервер offline, VPN disconnected, Telegram unavailable отображаются независимо.
- Отказ камеры/VPN/биометрии оставляет работоспособный выход и объяснение.
- Долгое ожидание не превращается в фиктивное одобрение или «Готово»; retry не дублирует действие.
- Back закрывает клавиатуру/лист/экран в ожидаемом порядке; подтверждение требуется только при реальной потере данных.
- Данные загружаются из реального источника; пустое состояние не заполняется фиктивными чатами.
- Отозванный доступ, неподдерживаемый ghost и остановленный плагин нельзя показать включёнными.

Скриншоты и UX-прогон выполняются после интеграции в Android. В этом дизайн-пакете native-render и аппаратные тесты не проведены.
