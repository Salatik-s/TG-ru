# Проверка дизайн-пакета

Дата: 2026-11-08. Проверено содержимое ресурсов, а не работа Android-приложения.

## Выполнено

- XML parsing через .NET: оба файла `colors.xml`, `dimens.xml`, `strings.xml` читаются без ошибок. Повторяющихся имён внутри файла нет.
- В light/dark одинаковые 15 color roles. В предложении 27 dimension resources и 85 русских строк.
- Рассчитан относительный контраст sRGB без прозрачности: 21 текстовая пара на тему. Проверены onPrimary/primary, onPrimaryContainer/primaryContainer, onError/error и шесть цветов текста на трёх основных поверхностях.
- Минимальный текстовый контраст light: **5.39:1**, error на surfaceContainerHigh. Dark: **7.40:1**, onPrimaryContainer на primaryContainer. Все проверенные пары превышают 4.5:1.
- Outline на трёх поверхностях: минимально **3.76:1** light и **4.50:1** dark. `outlineVariant` предназначен только для декоративного разделителя, не для единственной границы ввода.
- Сценарии отделяют неизвестный статус от отказа, одобрение от VPN и VPN от Telegram. Строки успешных действий требуют подтверждения фактической операции.
- Прочитана появившаяся версия `server/access.mjs`: добавлено сопоставление `new/pending/approved/blocked/revoked`, ошибок приглашения и cooldown. Отмена/отклонение заявки помечены как отсутствующие в текущем контракте.

## Не проверено

Android resource compilation/AAPT, сопоставление ролей с существующей темой, native layout, TalkBack, font scale, system insets, system Back, аппаратный VPN, состояние Telegram, работа сервера, хранение локальных копий и разрешения плагинов. При начале работы Android UI-базы в `familygram` не было. Браузерный макет не использовался как доказательство native-качества.

Дизайн-пакет содержит спецификацию и ресурсы для интеграции, а не готовые экраны. Нет оснований объявлять UX или безопасность проверенными в приложении.

## Порядок интеграции

1. Сопоставить существующие модели состояния/темы Android-базы со спецификацией; сохранить рабочие Telegram-компоненты.
2. Утвердить серверные статусы заявки и отзыва, область VPN, факт блокировки трафика. Удалить из UI строки возможностей, которых реализация не поддерживает.
3. Реализовать onboarding и семейные настройки на базовых Android-компонентах. Переносить ресурсы из `android-res` в настоящий модуль только после проверки конфликтов.
4. Пройти матрицу в `flows.md`, снять native light/dark screenshots с увеличенным шрифтом. Статические значения контраста не заменяют проверку итоговых alpha, ripple, overlay и dynamic colors.
5. Дополнительные функции включать по одной после проверки реального поведения. Установленный плагин не получает зелёный статус безопасности автоматически.
