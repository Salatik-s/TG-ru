# Isolated Android runtime QA

Run `Prepare.ps1`, then `node backend.mjs`. Preparation restricts the private directory ACL to the current Windows user and SYSTEM. Secrets and SQLite live only in `%USERPROFILE%/.codex/private/familygram-qa`; no production server, Windows DNS, or certificate trust is changed. Fresh local CA and server certificate are valid for three and two days. Preparation refuses an almost-expired existing certificate; use a new isolated private directory after manually archiving the previous run rather than overwriting its state.

API binds **127.0.0.1:8443**, owner control binds **127.0.0.1:18444** with a separate 256-bit bearer secret. Both use the existing production Access/API/Push classes. QA only substitutes gateway configuration: it supplies a random public key and approved device UUID, with emulator destination 10.0.2.2:18443. No gateway listens there; this tests enrollment, authorization, native startup, gate navigation and revocation, not Telegram connectivity.

The completed runs use the separate same-signer instrumentation APK in `instrumentation/`. Only that test process trusts the public QA CA and routes the API through the loopback CONNECT bridge. Production APK trust, Windows trust/DNS and the emulator system trust store remain unchanged. Do not add trust-all TLS or bypass the access gate. See `instrumentation/QA-RESULT.md` for actual results and limits.

`credentials.json` contains one initial one-use invitation for automation to read privately. `node control.mjs list` lists fingerprints; `approve FULL64HEXID` and `revoke FULL64HEXID` use real owner transitions. `invite` saves a replacement invitation to the private credentials file without printing it. Owner bearer is never passed to the APK. Logs contain no request URLs, code, token or key.

Suggested sequence: wrong code → 300-second server cooldown; clear/reinstall app to create a new Keystore installation; use the private invitation → pending; approve matching fingerprint → native startup and Telegram phone screen; revoke → gate closes and native lease stops. Do not enter a real Telegram account. A loopback health response means only this QA service is ready. Record emulator and ARM device results separately.

`node interop.mjs` independently compiles the real overlay `FamilyProtocol.java` with `ProtocolInterop.java`, using `JAVA_HOME` or the installed Android Studio JBR. It tests Java validation and exact UTF-8 SHA256withECDSA signatures against Node Access, including peppered invitation commitments, cooldown, approval, replay and malformed messages. Generated class files and SQLite data stay in a new private temporary subdirectory and are removed after the test; private keys pass only through process stdin. This test does not modify the running QA database, APK, or live service and is intentionally outside deploy tests.
