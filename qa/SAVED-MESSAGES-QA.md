# Saved Messages transport/media QA — prepared, not executed

User authorization is limited to synthetic tests in Saved Messages. Root coordinates the physical device `320245603330`; this preparation performs no adb action and sends nothing. Complete the production WSS repair and observe a genuine connected session before sending test data. Preserve the installed application and its data.

## Recommended order

1. **Text:** one uniquely tagged synthetic text sent to self; require an actual server response/acknowledgement, not merely a local bubble.
2. **Document:** a uniquely named 1 MiB synthetic binary, through the ordinary document upload path; record successful server acknowledgement and the new document's byte size.
3. **Fresh download:** fetch only that newly created document, bypassing the upload's local cached copy, and compare SHA-256 against the generated fixture. A local-open or cache-hit is not download evidence.
4. **Photo:** a generated color-grid PNG sent as a photo, followed by a fresh download of the returned photo variant. Verify successful image decoding and dimensions. Telegram's image conversion means the original byte hash need not match.
5. **Video/audio:** generated three-second color bars and a tone, never camera/microphone input. A video must be sent through the normal video path, and voice through the voice path to claim those UI features tested; sending an MP4/OGG as a document only tests generic files. Verify actual acknowledgement, fresh download and decodable duration/content.

Use a unique run marker in generated names/text. Stop after the first timed-out operation, record the bounded result and connection state, and avoid automatic duplicate sends. Do not delete pre-existing messages or clear application/media caches. Cleanup of test messages is separate from transport verification and must target only this run's exact acknowledged IDs if requested.

## Two grounded implementation options

**Existing UI/client pipeline (preferred for full app behavior):** launch normally and pass the family gate, choose the currently selected authenticated account, retain its self ID only in process memory, and present `ChatActivity` with `Bundle.user_id=selfId`. The pinned app already uses this route for Saved Messages (`LaunchActivity.java:647`). Reconfirm `ChatActivity.getDialogId()==selfId` and the same account immediately before a send. Do not enumerate dialogs, read view texts/history, take screenshots, or navigate the picker to another recipient. Generated attachments must come from the test's dedicated directory. The ordinary APIs are `SendMessagesHelper.SendMessageParams.of(String,long)`, `sendMessage(SendMessageParams)`, `prepareSendingDocuments`, `prepareSendingPhoto` and `prepareSendingMedia` in the pinned source. Long media overloads must be matched against actual DEX before reflection; do not infer overloads by argument count alone.

**Bounded transport RPC probe (easier to isolate from private content):** use the existing account's ConnectionsManager with `TL_inputPeerSelf`, a new random_id, and only generated bytes. Ordinary authenticated sendMessage/sendMedia requests must not carry `RequestFlagWithoutLogin`; that would mask native login-state problems. Observe only the callback belonging to the test request, identify its own `updateMessageID.random_id`, then request only that exact new message ID when media location metadata is needed. Never request dialog history, search messages, or dump Updates/callback objects. A direct RPC probe tests the authenticated upload/download chain, but does not establish that all native photo/video UI preparation works.

Do not use destination names, usernames, a guessed numeric ID or a general share recipient chooser for automated sending. `TL_inputPeerSelf` provides the tightest destination scope for a direct RPC test. Upstream request/send plugins can replace requests (`SendMessagesHelper.java:4500`, `ConnectionsManager.sendRequestInternal`), so an automated probe should abort if `PluginsController.hasSendMessageHooks()` or `hasAnyRequestHooks()` is true rather than changing the user's plugin settings.

## Fresh download without touching private caches

For a known newly acknowledged test document, keep its document metadata in memory and build `TL_inputDocumentFileLocation` using that response's id/access_hash/file_reference and empty thumb_size. Invoke `TL_upload_getFile` against that document's dc_id, in bounded aligned chunks, and hash only returned bytes of this synthetic file. Save them only in the test's private directory if needed. Do not print location IDs, hashes used for authorization, file references, or response objects. Handle CDN redirects explicitly or return a bounded unsupported result; do not label a cache hit/download timeout as success.

This bypasses FileLoader's cache and tests network download. A separate FileLoader/UI test can subsequently verify normal playback. If forcing that path to download again, remove only an exact newly created fixture cache file after ownership/path/hash checks; never clear the overall Telegram cache.

## Evidence and limits

Allowlisted output: step, result, duration, generated fixture size/SHA-256, byte count, downloaded synthetic-file SHA-256, media dimensions/duration, numeric connection state and numeric error code. Keep self IDs, message IDs, document locations, random IDs and callbacks in memory; do not print user IDs, phone numbers, access keys, actual messages, raw errors or private attachment names.

Use `messageReceivedByServer` / `messageSendError` only for test messages already correlated to this run; unrelated NotificationCenter events must not be read or logged. Local progress reaching 100% alone is not server acceptance. A downloaded byte hash match is stronger evidence than a thumbnail or successful local open.

Important pinned behavior: **zero WriteToSocketDelegate callbacks is not failure evidence for Generic requests.** Native ConnectionsManager invokes that callback for download/upload connection types, not ordinary Generic help/send RPCs. A real Generic server response can legitimately arrive with a zero write counter.

Instrumentation restarts the target process rather than attaching to the current process. Root should preserve live diagnostics first, and only then run any authorized harness. Current diagnostic APK does not send messages; it should remain separate from a future explicitly invoked Saved Messages sender.
