## 12 ноября 2026. Хранилище Billing

Результат сохранён в приватном репозитории. [Черновик PR №1](https://github.com/Salatik-s/TG-ru/pull/1).

**Изменения**

- `billing/database.mjs` открывает отдельный SQLite-файл и применяет версионированную миграцию в транзакции. Если указан существующий файл Gateway или неизвестная версия схемы Billing, открытие завершается ошибкой.
- `billing/migrations/001-initial.sql` создаёт таблицы аккаунтов, сессий, восстановления, устройств, платежей, подписок, выдач, спорных платежей и аудита. Схема ограничивает число активных устройств тремя, требует уникальный номер транзакции провайдера и проверяет принадлежность источника подписки. При удалении аккаунта связанные строки удаляются, платёж остаётся без ссылки на аккаунт. Правило изменения и удаления записей аудита действует на уровне БД, сроки очистки будут применяться фоновой задачей.
- `billing/test/database.test.mjs` проверяет миграцию и ограничения на реальном SQLite. `QUESTIONS.md` фиксирует отсутствующие разделы и открытые решения.

**Проверено локально на Node.js 24.16.0**

```powershell
node --test billing/test/database.test.mjs
Push-Location server
node --test
Pop-Location
```

Billing — 7 из 7. Шлюз — 59 пройдено, 3 пропущено (интеграционные сценарии с реальным Xray). Сборки preview9–17 на устройстве не прогонялись, протокол допуска в этой задаче не менялся. Изменений интерфейса нет. Выкладки на хост и запуска платежей не было.

Схема пока не хеширует пароли и не проверяет токены сама. Обработчики удаления аккаунта должны записывать отзыв Gateway в той же транзакции, что и локальное удаление. Обработчики оплаты и возвратов должны атомарно менять срок и писать событие в очередь доставки.
