# Шлюз Store

Кабинет и шлюз запускаются отдельными процессами. Доступ к Telegram проходит через выделенный экземпляр Xray. Подписки и пароли остаются в базе кабинета. Шлюз получает идентификатор ключа установки и два срока в подписанном запросе на loopback. Приглашения старых сборок используют прежний шлюз.

Кабинет разрешает активацию после запуска пятичасовой пробы или выдачи из консоли. Android доказывает владение закрытым ключом Keystore. Только после проверки кабинет запрашивает у шлюза профиль REALITY. Срок выдачи ограничен 75 секундами и окончанием доступа. Приложение продлевает его подписью устройства. При отзыве дальнейшее продление прекращается. Существующее соединение закрывается по окончании уже выданного допуска, максимум через 75 секунд. Добавление установки и удаление истёкших UUID сейчас перезапускают выделенный Xray Store и могут кратковременно прервать другие подключения Store.

## Проверка по USB

Для обоих процессов нужен Node.js 24 и проверенный Xray. Запустите из корня проекта в PowerShell. Переменные наследуются обоими процессами. Секрет генерируется для сеанса и не выводится в консоль.

```powershell
$env:STORE_GATEWAY_SECRET = [Convert]::ToHexString([Security.Cryptography.RandomNumberGenerator]::GetBytes(32)).ToLowerInvariant()
$env:STORE_GATEWAY_QA = '1'
$env:STORE_GATEWAY_DIR = Join-Path $PWD '.private/store-gateway-qa'
$env:XRAY_BINARY = (Resolve-Path 'C:/path/to/verified/xray.exe').Path
Start-Process node.exe 'server/store-gateway-main.mjs' -WorkingDirectory $PWD -WindowStyle Hidden
node local-store/main.mjs
```

Для локальной проверки через уже запущенный Happ с SOCKS на `127.0.0.1:10808` задайте `STORE_GATEWAY_QA_SOCKS_PORT=10808` перед стартом шлюза. По умолчанию Xray в QA направляет трафик Telegram напрямую. В обоих случаях вход Xray слушает только loopback.

```powershell
adb -s $testDevice reverse tcp:48185 tcp:48185
adb -s $testDevice reverse tcp:28443 tcp:28443
```

Для чистого профиля сначала проверьте отказ аккаунту без доступа. Затем запустите пробу в кабинете и активируйте установку. Для ручной выдачи повторите с другим аккаунтом и свежим Android-профилем.

```powershell
node local-store/owner.mjs grant qa_login 1 --reason test
```

В QA можно проверить счётчики байтов Xray на ПК. Счётчики суммарные и доступны только через loopback. Для прямого маршрута используйте `test-direct` вместо `test-socks`.

```powershell
& $env:XRAY_BINARY api statsquery --server=127.0.0.1:28444 -pattern 'outbound>>>test-socks>>>traffic'
```

## Публикация

Для запуска на хосте задайте обоим процессам общий секрет в закрытом файле окружения. Для шлюза укажите `STORE_GATEWAY_HOST=tg.24projects.ru`, отдельный каталог данных, путь к Xray и `STORE_GATEWAY_EGRESS_FILE` с проверенными зашифрованными исходящими маршрутами. Для кабинета задайте `TG_RU_STORE_PUBLIC_ORIGIN=https://tg.24projects.ru`. Кабинет и служебный API шлюза слушают только `127.0.0.1`. Для Store APK с параметром сборки `--public` нужен доступ к TCP 28443. Режим QA и его порт статистики на рабочем хосте отключены.

Store preview23 использует WSS на `https://tg.24projects.ru/v1/store-transport`, если сервер выдал этот профиль. Nginx завершает TLS и передаёт WebSocket в Xray на `127.0.0.1:28445`. WSS использует тот же временный UUID и те же ограничения на адреса Telegram, что и REALITY. Preview22 и локальный режим QA используют REALITY.

В действующем виртуальном хосте Nginx передавайте страницу Store и её API в кабинет на `127.0.0.1:48185`, сохранив `Host: tg.24projects.ru`. Существующие точные маршруты `/index.html` и `/download/TG-ru.apk` обслуживают метаданные обновления и защищённую загрузку прежнего релиза. При публикации сервер проверяет получение ответа MTProto по REALITY и WSS, прежнюю загрузку и API на порту 8443. После публикации проверьте вход в Telegram на телефоне через мобильную сеть.
