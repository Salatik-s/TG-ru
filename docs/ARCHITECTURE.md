# Сеть, данные и права

## Два независимых входа

Допуск к семейному приложению и авторизация Telegram — разные механизмы. Семейный сервер подтверждает право конкретной установки пользоваться шлюзом. После этого Telegram сам проверяет номер, код входа и, при наличии, облачный пароль. Сервер семейного допуска не заменяет Telegram и не получает права администратора Telegram-аккаунта.

## Идентичность установки

Приложение создаёт P-256 ключ в Android Keystore. Сервер выдаёт короткоживущее одноразовое задание, а установка подписывает точное действие и его параметры. Доказательство проверяется по зарегистрированному открытому ключу; повторы и изменение действия отклоняются.

Приглашение одноразовое. После него установка остаётся в ожидании до одобрения владельцем. Каждая неверная попытка вводит паузу 300 секунд; десять последовательных ошибок блокируют установку. Есть дополнительные временные IP-лимиты. Постоянный аппаратный запрет по MAC не используется: мобильные ОС не предоставляют такой надёжной идентичности приложению.

Переустановка с потерей Keystore создаёт новую установку. Владелец должен выдать новое приглашение и одобрить её. APK сам по себе не даёт доступ к серверу.

## Права владельца

Ровно одна одобренная установка назначается владельцем через локальный административный интерфейс хоста. Публичного HTTP-метода самоназначения нет. Установка владельца может:

1. Создать ограниченное по сроку одноразовое приглашение.
2. Увидеть список установок и их статусы.
3. Одобрить ожидающую установку после сверки отпечатка.
4. Отозвать другое устройство.

Сервер проверяет роль и подпись при каждом действии. Обычное одобренное устройство не становится администратором, даже если у него такой же APK. Видимость кнопки в интерфейсе не является проверкой полномочий; запрет обеспечивается сервером. Управление собственным допуском с телефона ограничено, чтобы не оставить семью без владельца случайным нажатием.

## Путь сообщений и файлов

TG-ru использует нативную интеграцию Telegram networking, встроенное транспортное ядро и собственный хост. Основной путь — VLESS внутри WebSocket с TLS на существующем доверенном HTTPS-входе. Сертификат и имя сервера проверяются. На хосте TLS завершается; внутренний WS-порт не опубликован наружу. Далее выбранный профиль выводит соединение через VPN-узел к Telegram DC.

Сам MTProto остаётся протоколом Telegram. Хост не хранит ключи авторизации Telegram, историю переписки или Telegram-сессии пользователей. Он видит сетевые метаданные маршрутизации и обслуживает транспорт. Облачные чаты продолжают храниться у Telegram; собственный шлюз не делает их сквозно зашифрованными секретными чатами.

ОС телефона может направлять соединение к хосту через уже включённый системный VPN. TG-ru не запускает второй системный `VpnService`. Это устраняет конфликт двух системных VPN-сервисов, но не доказывает работоспособность с любым сторонним VPN, split tunneling или сетевыми фильтрами.

## Выбор серверного выхода

Сервер использует локально сохранённые native VLESS/Trojan/Shadowsocks-профили владельца, а не загружает подписку при каждом запуске. Прямой выход к Telegram не служит обходным fallback при отказе VPN. Выбор подтверждается ответом MTProto `resPQ` с совпадающим nonce. Активный маршрут перепроверяется, а неисправный заменяется проверенным доступным узлом. Обычные узлы проверяются перед БС-резервом, если резерв существует в конфигурации.

В использованном snapshot было 20 обычных профилей и ни одного БС-профиля; это состояние конкретного развёртывания, а не гарантия существования резервного узла. Один хост остаётся единой точкой отказа.

## Аренда и отзыв

Допуск обновляется примерно раз в минуту. Нативная аренда ограничена 75 секундами и учитывает сон устройства. При отзыве, остановке или истечении аренды транспорт закрывает активные соединения и не должен продолжать соединение без нового действующего допуска. Перезапуск шлюза при изменении списка клиентов закрывает старые серверные сессии.

## Уведомления

Сигнал Telegram SimplePush содержит версию события. Семейный сервер передаёт сигнал через авторизованный SSE, после чего приложение получает содержимое по своему MTProto-соединению. Relay не хранит текст сообщения. Фоновая работа Android зависит от разрешений, энергосбережения и условий сети; длительное испытание уведомлений отдельно от короткого сетевого теста ещё требуется.

## Где хранятся данные

| Данные | Где |
|---|---|
| Приватный ключ установки | Android Keystore телефона |
| Telegram-аккаунт, локальный кэш, локальная история удалений | Приложение на телефоне; облачная история также у Telegram |
| Открытые ключи, статусы устройств, ограничения попыток | SQLite собственного сервера |
| VPN-профили и ключи шлюза | Приватный каталог данных на хосте |
| Код/ввод/вывод встроенного Python | Локальная ограниченная среда телефона |
| Документ для просмотра | Локальный файл; изолированному процессу выдаётся только дескриптор чтения |
| Ключ подписи Android-релизов | Отдельное приватное хранилище владельца, вне Git |

## Границы

Вредоносный плагин в обычном менеджере, скомпрометированный телефон, администратор хоста, ошибки клиента и ограничения Telegram остаются отдельными рисками. Ограничения встроенного Python не распространяются на весь процесс приложения. Ни режим призрака, ни собственный VPN не гарантируют абсолютную анонимность или постоянную доступность.


## Локальные инструменты preview11

Python запускается явной кнопкой под сообщением с кодом; вывод вставляется только в локальную панель. Это не отправка нового Telegram-сообщения и не изменение сообщения на сервере. Ограниченная Pyodide-среда сохраняется; основной сценарий работает без перехода в отдельный редактор. Вывод 15 sp можно раскрыть стандартным диалогом. Лимит исполнения 10 секунд отделён от bootstrap runtime до 30 секунд.

Документы разбираются локальным изолированным процессом. PDF передаётся PdfRenderer и собственному масштабируемому view, DOCX/ODT преобразуются в ограниченную разметку средствами собственного renderer. Документ не может передать HTML/CSS/JavaScript напрямую в WebView; активные ссылки, JS, файловые URI и внешняя сеть отключены.

Расшифровка использует только `SpeechRecognizer.createOnDeviceSpeechRecognizer` и Android file-input contract с дескриптором PCM. Отдельный server-transcription API и Whisper-runtime не участвуют в production; соответствующие эксперименты архивированы. Запись сначала может скачиваться обычным Telegram-путём, но дополнительной выгрузки записи для ASR не предусмотрено. Штатная загрузка отсутствующей языковой модели — отдельный системный сетевой шаг.

Системный ASR-провайдер и его модели являются частью ОС. Доверие к правильному file-input подтверждено только для определённой Android/provider-конфигурации. При неподтверждённом провайдере функция не должна автоматически переключаться на микрофон или облачное распознавание. Новый `FamilyVoiceTranscription` подключён к штатному `TranscribeButton`, его видимости, нажатию и подписи voice caption. Удалённый ранний `FamilyTranscriptionActivity` не является пользовательским интерфейсом этой версии. `FamilyLocalTranscriber` не имеет UI и не вызывает Premium/cloud RPC. Локальный результат получает отдельную отрицательную идентичность и ограниченный кэш памяти, без записи в `MessagesStorage`.

Подробности — [NATIVE-SPEECH.md](NATIVE-SPEECH.md).


## Интерфейс preview12

Серверные owner/WSS/VPN-пути сохраняются. Изменения Android касаются родного оформления настроек призрака и собственного foreground-service уведомления. Его статус берётся из штатного ConnectionsManager выбранного аккаунта и семейного допуска; рабочий SSE не используется как подмена состояния Telegram. ID системного канала сохраняется.
