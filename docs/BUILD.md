# Сборка и обновление

## Что находится в Git

Этот репозиторий содержит собственные модификации, нативные исходники/пины, сервер, скрипты развёртывания и QA. Большие upstream-деревья, скачанные инструменты, промежуточные DEX, APK, private signing и локальные данные исключены. Полный исходный клиент доступен по закреплённому commit из `upstream-release.json`; лицензии исходных проектов сохраняют силу.

Текущая сборка использует закреплённый APK exteraless и компилирует собственные Java/Go/C++-добавления. Это не завершённая полная сборка upstream через Gradle. Скрипты промежуточных preview применяются в своём порядке и требуют соответствующего базового артефакта с точной контрольной суммой. Нельзя подставить произвольный похожий APK и считать результат эквивалентным.

Для Store preview23 базой служит проверенный preview20. Декодируйте его Apktool с `--no-src` в `build-support/work-store-10024/decoded`. Запустите `build-support/prepare_store_preview.py --base <preview20.apk> --work build-support/work-store-10024`. Соберите `libfamilytunnel.so` из текущего `tunnel/` для arm64-v8a и x86_64 и замените соответствующие файлы в `decoded/lib/`. Соберите ресурсы Apktool в `rebuilt-unsigned.apk` внутри рабочего каталога. Передайте SHA-256 этого файла и рабочий каталог в `repack_overlay.py`, затем подпишите полученный `SAA-UNSIGNED.apk` через `build-support/Sign.ps1`. Для QA используется локальный кабинет по USB. Параметр `--public` на шаге подготовки выбирает рабочий HTTPS и исключает разрешение на loopback HTTP. [Параметры шлюза](STORE-GATEWAY.md)

## Инструменты

Для Store preview26 выполните те же шаги в `build-support/work-store-10027` и добавьте `--device-updates` к `prepare_store_qa_preview.py`. Привязанный Android запрашивает одноразовую загрузку APK с подписью ключом установки. Кабинет по-прежнему скачивает APK через браузерную сессию.

Для Store preview25 используйте подписанный preview24 с SHA-256 `e00e29122c085fe511c2861ce326750696f47e61a6caeb34c0f799c1d80ee5d7`. Декодируйте его через Apktool с `--no-src` в `build-support/work-store-10026/decoded`. Запустите `prepare_store_qa_preview.py` с путями к базовому APK и рабочему каталогу. Соберите `rebuilt-unsigned.apk` через Apktool, затем передайте его SHA-256 и рабочий каталог в `repack_overlay.py`. Параметр `--docs-jars` задаёт путь к зависимостям просмотрщика, если они лежат в другом рабочем каталоге. Подпишите `SAA-UNSIGNED.apk` через `Sign.ps1`. Сервер Store публикует метаданные для кнопки «Проверить обновления» по `/api/store/release`.

Использованы Windows PowerShell, Python 3, JDK с javac 17, Android SDK Platform 35 / Build Tools 37.0.0, D8, AAPT2, zipalign, apksigner, Apktool 3.0.3, Go и Android NDK для нативных библиотек. Потребуются инструменты и зависимости, указанные в README каталогов `native`, `tunnel`, `calls`, `build-support`.

Исходные контрольные суммы находятся в `upstream-release.json`, lock-файлах и отчётах сборки. Приватный ключ подписи не включён. Для обновления уже установленного TG-ru требуется тот же ключ; новая подпись не является совместимым обновлением.

Часть вспомогательных скриптов пока содержит пути рабочей Windows-машины. Перед сборкой на другом компьютере их следует явно адаптировать. Документация не утверждает, что свежий clone одной командой уже воспроизводит все preview без локальных базовых артефактов.

## Порядок проверки APK

1. Проверить SHA-256 исходного APK и нативных входов.
2. Подготовить отдельный staging каталог, не менять исходный APK.
3. Собрать реальные нативные библиотеки для arm64-v8a и x86_64.
4. Скомпилировать overlay Java и зависимости, собрать ресурсы/smali.
5. Убедиться, что все закреплённые public resource IDs сохранены и классы не дублируются между DEX.
6. Проверить нативные ABI, зависимости и требуемые экспортируемые символы.
7. Выполнить 16 КиБ ZIP alignment, подписать ключом владельца, проверить v2/v3 подпись и целостность ZIP.
8. Установить как обновление с сохранением данных и проверить на физическом телефоне. Не выполнять `pm clear`, удаление приложения или миграцию application ID.
9. Зафиксировать SHA-256 итогового подписанного APK, versionCode, versionName, сертификат и результат runtime-тестов именно этой версии.

`build-support/README.md` и отчёты ранних preview содержат историю этапов; их старые названия и границы относятся к указанным там версиям. Актуальное имя пользовательского файла — `TG-ru.apk`.

## Проверки исходников

Серверные тесты запускаются в каталоге `server`:

```powershell
node --test
```

Опциональные тесты с настоящим Xray требуют своего тестового бинарного файла и окружения. Пропущенный тест не равен пройденному. Тесты native/Go и Android instrumentation имеют собственные инструкции в соответствующих каталогах.

## Развёртывание сервера

Скрипты работают в области `/opt/familygram` и Compose-проекте `familygram`. Существующие сайты, host nginx, VPN-контейнеры, тома и порты 80/443 сохраняются. Используется существующий сертификат `24projects.ru`; новый домен не требуется. Новый внешний API/WSS-вход — TCP 8443, legacy REALITY — TCP 18443. Сетевой firewall провайдера настраивается отдельно владельцем.

Сначала проверяется план, затем выполняется обновление:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\deploy\Deploy.ps1 -PlanOnly
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\deploy\Deploy.ps1
```

Пароль SSH вводится в обычном системном приглашении; он не зашивается в скрипты. Диагностика RAM информационная: пользовательские пороги допуска и собственные memory caps удалены по решению владельца. Запуск проверяется по health и фактическим ошибкам служб, а не произвольному порогу RAM.

`Fix-Transport.ps1`, `Fix-Owner.ps1`, `Fix-Egress.ps1` и `Retry.ps1` — адресные repair-скрипты для конкретного ранее загруженного staging. Они проверяют точные файлы и hash. Они не являются универсальным обновлением любого сервера. Генераторы repair payload и соответствующий текущему staging отчёт должны использоваться согласованно; устаревший payload нельзя применять вслепую.

Опциональная остановка VoiceRooms затрагивает только предварительно проверенные контейнеры его проекта, сохраняет данные и печатает команду возврата. Само по себе наличие такой опции не разрешает останавливать другие проекты.

## Администрирование

Права телефонного владельца назначаются однократно локальным административным интерфейсом сервера для уже одобренного ID установки. В обычном семействе APK этот ID не зашит. Потеря телефона владельца требует административной перепривязки с хоста; общий APK не должен уметь самостоятельно назначать нового владельца.

Перед публикацией нового Release проверяются приватная видимость репозитория, отсутствие дополнительных collaborators, состав исходников и отсутствие секретов. Бинарный APK загружается как asset приватного Release, а не в Git: его размер превышает лимит обычного GitHub blob.


## Локальные возможности preview11

Новый Office renderer и масштабируемый PDF входят в Android overlay. Проверять нужно настоящий pinch/double-tap/pan, повторный high-resolution render и навигацию страниц; успешная компиляция или один снимок не подтверждают этот UI-путь.

Для расшифровки используется Android on-device API, а не скачанный Whisper runtime. В APK не добавляется Whisper-модель. Доступность требует Android API 33+, системного on-device recognizer и установленной языковой модели; управляемая загрузка модели использует API 34+. Подтверждённый file-input provider закреплён по версии Android и пакета, поэтому смена ОС/провайдера требует повторного теста. Совместимость базового мессенджера со старыми Android не означает доступность локальной расшифровки на них.

Production-сервер остаётся прежним owner/WSS/VPN baseline. Архив `qa/unreleased/server-transcription`, если присутствует в исходниках, не является инструкцией развёртывания. Не применять старые Whisper/ASR repair-команды к хосту.

iOS/IPA отложен пользователем до отдельного этапа. Текущая работа и Release ограничены Android; iOS workflow и jobs в этом обновлении не запускаются.
