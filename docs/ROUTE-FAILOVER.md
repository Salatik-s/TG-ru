# Android: резервный маршрут

Обычный маршрут идёт через WSS. С согласия пользователя приложение пробует REALITY, если Telegram не соединяется 10 секунд подряд при доступной сети и действующем допуске. Через 10 минут оно пробует вернуться на WSS. Во время звонка переключение откладывается. Если нет сети, отсчёт 10 секунд сбрасывается. Для смены маршрута нужен свежий ответ API с действующим допуском; смена транспорта не подменяет API.

При первом открытии списка чатов приложение спрашивает разрешение. По умолчанию REALITY отключён. Решение можно поменять в «Настройки → Соединение». Смена транспорта не запускает Activity и не отправляет пользователя в список чатов.

## Проверено

- JVM: границы 10 секунд и 10 минут, сброс ожидания, отказ от REALITY и перенос переключения на время после звонка.
- Подписанный APK установлен на отдельный Android 11 эмулятор. Инструментация проверила обе кнопки первого вопроса, отсутствие повторного вопроса после отказа, изменение выбора в настройках и сохранение после повторного открытия.
- APK: `0.1.0-preview18`, код `10019`, SHA-256 `fbb3ff27cc5b4d8c1aff4758c512f580a1bb55b0ead549032ff37ecf2c4bdf62`. Проверены подпись Android v2/v3, выравнивание, неизменность прежних идентификаторов ресурсов, отсутствие дубликатов DEX-классов и совпадение исходных DEX и нативных библиотек с preview17.
- На втором физическом Android отправлено приглашение с телефона владельца. В списке владельца устройство «Тестовое Android-устройство» получило статус «Доступ разрешён». Установщик Android обновил приложение до `10019` поверх `10018` из локального APK. Тестовый аккаунт сохранился, список чатов открылся, диалог согласия разрешил автоматическое переключение.

## Передача работы · 12 ноября 2026

### Физический замер на preview19

На втором телефоне установлена подписанная preview19 (`10020`). До сбоя список чатов показывал «Telegram». Временный VPN ограничивался приложением TG-ru и IP шлюза, ретранслятор пересылал TLS без расшифровки. Перед блокировкой выделили WSS по наблюдаемому набору TLS-групп и ALPN. Во время отказа WSS отдельный HTTPS-запрос до API прошёл.

- От первого отказа WSS до первого TCP-соединения REALITY прошло **10,631 с**. От включения фильтра до него прошло 11,283 с. После этого шапка снова показывала «Telegram».
- Первое TCP-соединение WSS после периода на REALITY открыто через **600,229 с**. Через этот интервал подтвердился возврат транспорта. Контрольное сообщение после возврата не отправлялось.
- На основном телефоне preview17 восстановил список чатов через Wi-Fi после переоткрытия. Мобильный сбой отдельно не локализован. По стеку найдено падение отложенного обновления настроек после закрытия экрана. В preview19 оно игнорируется. Проверка вызова без Activity прошла на JVM. Сетевые события теперь сбрасывают отсчёт и без активного списка чатов, время диагностики фиксируется в момент события.

### Preview20 без режима призрака

Из настроек, меню чатов и вариантов заголовка удалены элементы призрака. Старый выбор заголовка с призраком заменяется на Telegram. Убраны активность и строки TG-ru для этого экрана. Патч закреплённой базы возвращает стандартную отправку статуса, прочтения, набора и просмотра, закрывает унаследованные переходы и отключает чтение, восстановление и запись архива удалённых сообщений. Старые настройки не могут включить эти функции. Файлы старого архива на телефоне не стирались. В базовом DEX остаются отключённые классы форка.

Сборка `0.1.0-preview20` (`10021`), SHA-256 `de059a2365b83d09e8abb72d564852110a7f60941c364eb7a0633a6d74818b94`. Подпись Android v2/v3 соответствует preview19. Проверены 10 DEX и 64 275 уникальных классов. `classes2.dex`, `classes6.dex`, `classes8.dex`, нативные библиотеки и assets побайтово совпадают с проверенной preview17. Пяти изменённым DEX применён патч для унаследованных точек входа, два последних содержат заново собранный overlay. APK установлен штатным установщиком на втором устройстве. Сессия сохранилась, список чатов открылся. В настройках и меню списка чатов пункта призрака нет. Хост и архивы старых сборок не обновлялись.

Для повторной сборки декодировать проверенную preview17 с помощью Apktool с исходниками, затем выполнить `prepare_route_update.py --preview 20` и `prepare_clean_privacy.py --retain-unchanged-dex` в одном рабочем каталоге. После сборки Apktool использовать `repack_overlay.py` с SHA-256 собранной основы и `Sign.ps1`. Системную проверку срока пробного доступа Store отслеживать в [отдельном проекте](https://github.com/Salatik-s/TG-ru/pull/8).

### Архив предыдущей остановки

По просьбе владельца работа остановлена перед началом сетевого замера. Время переключений на физическом телефоне ещё не измерено. Android отклонил установку временного тестового APK по USB. Подписанный файл `TG-ru-Route-Test.apk` лежит в «Загрузках» второго телефона, размер и SHA-256 сверены после копирования. Тестовое приложение не установлено, VPN не запущен. Локальный ретранслятор остановлен, два временных правила ADB reverse удалены.

1. Продолжить в [PR Android](https://github.com/Salatik-s/TG-ru/pull/6) и рабочей копии `C:\Users\andre\Documents\Codex\TG-ru-android-route-failover`. Доступ к приватному репозиторию определяется аккаунтом GitHub. На втором телефоне оставить установленную preview18 и действующую сессию. Основной телефон нужен только для действий владельца или отдельно согласованного тестового звонка.
2. На этом ПК исходники временного стенда, подписанный APK и ретранслятор находятся в `%TEMP%\tg-ru-network-qa`. Перед продолжением убедиться, что файла `block-wss.flag` нет. Запустить `node "$env:TEMP/tg-ru-network-qa/relay.mjs"` и на втором устройстве восстановить ADB reverse для `tcp:48217` и `tcp:48218`. Ретранслятор слушает loopback на ПК и пересылает TLS без расшифровки. У него проверен локальный TLS-запрос к шлюзу. Работа VPN на телефоне ещё не проверена.
3. На Xiaomi установить временный APK через «Проводник», открыть «TG-ru · тест сети» и подтвердить системное разрешение VPN. Сервис маршрутизирует только трафик TG-ru к IP шлюза. Для калибровки проверить в журнале ретранслятора успешный API и обычный WSS отдельно. Фильтр отличает WSS по предложению только HTTP/1.1 в TLS, это предположение нужно подтвердить на телефоне до блокировки.
4. Создать `block-wss.flag` и проверить, что WSS перестал работать, а API остаётся доступен. Снять время перехода с «Соединение» на REALITY по журналу приложения и фактическому соединению с портом 18443. Затем удалить флаг и дождаться возврата на WSS через 10 минут от перехода. Проверить, что чаты остаются открыты и обмен данными восстановился. По завершении остановить VPN, удалить временное приложение и правила ADB reverse.

Тестовые APK устанавливать только на второй телефон. Выкладка на хост и отключение старых сборок для этой проверки не нужны. Следующая фаза по ТЗ зафиксирована в [журнале работ](https://github.com/Salatik-s/TG-ru/blob/sukhovskiy.a.a/phase-1-compat/docs/WORKLOG.md).
