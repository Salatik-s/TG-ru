# Системная локальная расшифровка Android

Статус: проверенный Android preview11. Штатная кнопка TranscribeButton на собственном synthetic Opus-сообщении открыла родную расширяемую подпись с локальным результатом. Проверка non-Premium flag показала кнопку без замка, затем флаг был немедленно восстановлен. Ранний отдельный Activity не входит в финальный UX.

## Что делает приложение

Пользователь нажимает обычную кнопку транскрипции Telegram в голосовом сообщении или видеокружке. Отдельный экран расшифровки не открывается. Видимость и нажатие интегрированы в штатный `TranscribeButton`; результат и состояние работы отображаются в штатной подписи сообщения. Если файл ещё не скачан, он получается обычным Telegram-путём. Звуковая дорожка декодируется на телефоне в mono PCM 16-bit / 16 kHz и передаётся системному on-device recognizer через pipe/file descriptor.

Дополнительной загрузки записи на семейный хост нет. Встроенный Whisper и сторонний облачный ASR не используются; Telegram Premium API для выполнения этой локальной операции не вызывается. Текст остаётся в родном пузыре/подписи сообщения. `FamilyVoiceTranscription` использует ограниченный кэш памяти: до 32 записей / суммарно 1 МиБ, текст одного результата до 64 КиБ. Данные не записываются в `MessagesStorage`, не добавляют новое сообщение и не вызывают Telegram RPC транскрипции. После завершения процесса локальный кэш не считается постоянной историей.

## Требования

- Android API 33+ с доступным системным on-device SpeechRecognizer.
- Установленная языковая модель для выбранного языка. Если её нет, UI предлагает штатную загрузку модели через Android; управляемая загрузка поддерживается с API 34.
- Отдельно подтверждённый контракт file input именно для установленного провайдера/версии ОС. OEM-провайдеры могут игнорировать EXTRA_AUDIO_SOURCE, поэтому одного флага наличия ASR недостаточно.

Production использует только `createOnDeviceSpeechRecognizer`, без автоматического fallback на микрофон или облачный recognizer. Если требование не выполнено, приложение показывает ограничение, а не подменяет источник звука.

## Что фактически проверено

На NX721J с Android 15 использовался Google AiAi service версии `12872254`:

`com.google.android.as/com.google.android.apps.miphone.aiai.app.AiAiSpeechRecognitionService@12872254`

Отдельное диагностическое приложение передавало synthetic русскую PCM-запись длиной 9,6 секунды. Разрешение RECORD_AUDIO у тестового UID было отозвано, а его microphone AppOp переведён в IGNORE (mode 1); диагностический caller permission был `false`. Распознавание вернуло полную тестовую фразу с контрольными словами и числами: «проверка», «телефон», «один два три», «два плюс два равно четыре».

Это подтверждает распознавание переданного файла при недоступном микрофоне тестового приложения в этой конфигурации. Это не испытание каждой модели телефона, языка, версии Google/Android и не гарантия точности на любой записи. Production-проверка версии ограничивает доверие к известной конфигурации; обновление требует повторной проверки.

## Модели и сеть

Русская модель первоначально отсутствовала. Она была загружена штатным Android triggerModelDownload, после чего file input сработал. Загрузка модели требует системной сети и места на телефоне; это отдельный этап, не загрузка голосового сообщения для распознавания.

Обычный сетевой путь Telegram остаётся `приложение → собственный хост → сохранённый VPN → Telegram`. Системная загрузка языковой модели не является Telegram-трафиком и не выдаётся за часть этого маршрута.

## Скорость и ограничения

Известный провайдер терял конец записи при мгновенной передаче всего PCM-файла. Поэтому production подаёт звук блоками по 40 мс с реальной скоростью 32 000 байт/с. Обработка занимает примерно длительность записи плюс запуск и завершение recognizer; обещания мгновенной обработки длинного файла нет.

Текущий вход ограничен 16 МиБ и длительностью до пяти минут. Декодер поддерживает распространённые аудио/видеоконтейнеры через Android codecs; штатная кнопка в этом UX предназначена для голосовых сообщений и видеокружков. Возможность декодирования других MIME не означает наличие кнопки под каждым обычным файлом/видео. Защищённые от пересылки, исчезающие и секретные media исключаются соответствующими проверками eligibility.

Точность зависит от качества записи, языка, шума и системной модели. Отсутствующая модель, непроверенный provider, неподдерживаемый codec и отмена показываются пользователю отдельным состоянием.


## Отдельная проверка декодера

Проверены 91 чистый PCM-fixture и дополнительные регрессионные проверки флагов extractor. На настоящем устройстве прошли полное декодирование AAC/MP4, Opus/OGG и точный WAV, отмена, отказ на повреждённом файле и видео без аудиодорожки. Исправлен случай конца потока: `sampleSize=-1` / `getSampleFlags=-1` распознаётся как EOF до проверки DRM-флагов, а не как ошибочная «защита записи».

Эти результаты относятся к декодированию, а не к гарантии ASR-точности или к сквозному UI-тесту новой native bubble интеграции. Финальная интеграция штатной кнопки/подписи проверена на synthetic записи. Все личные записи и их содержимое исключены из QA-артефактов репозитория.

## Исключение личных данных из QA

В репозиторий допускаются только собственные синтетические fixtures и их обезличенные результаты. Пользовательские голосовые записи, их текст, скриншоты и содержимое личного чата не включаются ни в исходники, ни в Release, ни в эту документацию.
