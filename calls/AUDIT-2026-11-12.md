# Call transport audit, 2026-11-12

## Confirmed boundaries

- The application routes the original call library's IP sockets through the native adapter and the approved Xray transport. P2P is disabled in `prepare_repack.patch_private_calls`; Telegram relay behavior is retained.
- Both phone outbound generation (`tunnel/config.go`) and imported server Vision egress (`server/egress.mjs`) already enable the client-only `-udp443` flow suffix. Adding this again or buying a second subscription is not a verified fix.
- Gateway routing permits both TCP and UDP through the selected encrypted egress. It blocks private/reserved destinations. Selection uses an MTProto/TCP probe; its success does not prove relay UDP works.
- Original ELF build ID guards are unchanged. The current 13.2.1 adapter is built against the exact verified original call library.
- No real call was placed and no live host state was inspected in this audit. The cause of the reported connecting hang remains unconfirmed.

## Added diagnostics

`FamilyCalls.diagnosticCounters()` returns ten process totals:

0. Virtual sockets opened
1. UDP target dial errors
2. UDP packets handed to transport
3. UDP packets returned from transport
4. UDP queue/send drops
5. TCP target dial errors
6. TCP bytes handed to transport
7. TCP bytes returned from transport
8. Transport stop requests
9. Currently registered virtual sockets

These are numeric, bounded in size, and contain no target IPs, payloads, keys, phone numbers, or peer identities. Sent counters only prove delivery to the local transport queue, not delivery to Telegram. Compare deltas during a call, rather than interpreting lifetime totals as a call result.

If socket opens do not increase during a real call, inspect call initialization and protocol negotiation. If UDP transmission increases without reception, investigate the whole UDP relay/egress path, with a real bidirectional probe; another subscription is useful only if it demonstrably supports that traffic. If stop counts increase during the hang, correlate with authorization lease and network changes. If both directions work, examine Telegram/WebRTC ICE and call-state transitions without recording audio or keys.

## Validation

Both ABI builds passed strict compiler checks. Both shared libraries passed export, RELRO, BIND_NOW, 16 KiB alignment, and static C++ linkage checks. The adapter smoke harness includes counter assertions and compiles for both ABIs. The ARM64 adapter smoke test passed on the connected Android 15 device, including the counter assertions. Full call validation still requires consenting participants and real audio in both directions, with phone VPN off and on.
